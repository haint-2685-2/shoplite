Setting up Vite with TypeScript

This very lab folder was created with the command below. The browser never sees a type: Vite strips them on the fly, and tsc checks them separately.

1. Create, install, run

npm create vite@latest module-3 -- --template vanilla-ts
cd module-3
npm install
npm run dev        # http://localhost:5173 — compiles .ts on every request
npm run typecheck  # tsc --noEmit: type errors only, writes nothing
npm run build      # tsc && vite build — a type error stops the build

2. What the template gives you

module-3/
├─ index.html        the entry point IS an html file, not a .js file
├─ package.json      devDependencies: typescript + vite, nothing else
├─ tsconfig.json     how strict tsc is, and what it may assume about the runtime
└─ src/main.ts       <script type="module" src="/src/main.ts"> — a .ts file, straight from HTML

In this repo src/ was removed: each lab folder holds its own index.html + main.ts, and vite.config.ts lists them so npm run build outputs every page.

3. tsconfig.json, line by line

OptionWhat it means here
"target": "es2023"Which JavaScript syntax the output may use. Modern browsers only, so no down-levelling.
"lib": ["ES2023", "DOM"]Which built-ins exist. Without DOM, document is an error.
"types": ["vite/client"]Adds Vite's globals: import.meta.env, ?raw imports, CSS imports.
"moduleResolution": "bundler"Resolve imports the way Vite does, not the way Node does.
"noEmit": truetsc never writes a .js file. Vite does the compiling; tsc is only the checker.
"verbatimModuleSyntax": trueType-only imports must be written import type, so a transpiler that sees one file at a time knows it can drop them.
"erasableSyntaxOnly": trueOnly syntax that can be deleted is allowed. enum generates code, so it is refused. Turned off in these labs so lab 1.2 can show one.
"strict": trueThe default since TypeScript 6 — the template does not even write it. v3-ts writes it anyway. See lab 2.4.
